## 一、先校准：Obsidian 不是笔记软件，是知识图谱引擎

《新手入门指南》里说过一句话：你的笔记存在自己电脑上、是纯文本 Markdown、永远属于你。这一节往前再走一步——**为什么这很重要**。

1. **本地优先 = 可控**：笔记是文件夹里的 `.md` 文件，你可以用任何编辑器打开、用 git 备份、用脚本批量处理。AI 工具（Claude Code / Cursor）能直接读整个 Vault 当上下文。这是云端笔记做不到的。
2. **纯文本 = 可迁移**：Markdown 是事实标准，十年后还能打开。你不会被某个软件的私有格式绑架。
3. **图谱 = 复利**：每加一条双向链接，整张网络的检索价值就涨一点。笔记越久，AI 能挖掘的关联越多。

> 一句话校准：**不要追求"记全"，要追求"连对"**。一条被十篇笔记引用的概念笔记，比十篇孤立的日记有用得多。

## 二、核心机制深化：链接 / 标签 / MOC 三件套怎么用

《新手入门指南》讲了语法，这里讲**怎么用才不烂**。

### 2.1 双向链接 `[[ ]]`：原子的艺术

- **一条笔记 = 一个概念**（原子化）。不要写"2026-08-21 学习日记"这种大杂烩，要拆成 `[[注意力机制]]`、`[[Transformer 架构]]`、`[[残差连接]]` 等独立笔记。
- **在写的过程中自然链接**：想到相关概念就 `[[链接]]`，别等写完再补。Obsidian 的输入联想（`[[` 后弹窗）让这事很顺手。
- **反链是金矿**：打开任意笔记，右侧"反向链接"面板显示"谁引用了我"。这是你知识网络的"被需要度"指标。

### 2.2 标签 `#`：做横向主题，不做分类

- 标签用于**跨文件夹的主题聚合**：`#电气` `#论文` `#待整理`。
- 别用标签代替文件夹。文件夹是"大类"（01-Concepts / 02-Books），标签是"你可以同时属于多个的主题"。
- 控制数量：标签超过 50 个就失去意义，定期合并近义词。

### 2.3 MOC：用笔记做目录（Map of Content）

MOC 是 Obsidian 最被低估的功能。它是一篇"索引笔记"，本身不装内容，只放链接，把某一主题下的原子笔记串起来。

```markdown
# MOC · 电力电子

## 基础
- [[PWM 调制]]  [[逆变拓扑]]  [[死区补偿]]
## 进阶
- [[并网控制]]  [[阻抗建模]]  [[弱电网稳定性]]
## 待读
- #待整理/电力电子
```

- 仓库里 `06-MOC/` 已给出 `MOC-学习笔记.md`、`MOC-研究.md`、`MOC-创作.md` 三个范本。
- **用法**：每进入一个新主题，先建 MOC；之后所有相关原子笔记都回链到它。MOC 就是你的"知识地图"。

## 三、插件体系：核心插件 + 社区插件怎么搭

Obsidian 的能力 = 核心插件（官方内置）+ 社区插件（社区开发）。

### 3.1 核心插件（设置 → 核心插件，建议全开这几个）

| 插件                  | 用途                        |
| ------------------- | ------------------------- |
| 日记（Daily notes）     | 每天自动建日记，配合模板              |
| 模板（Templates）       | 新建笔记套用模板（后面 Templater 更强） |
| 大纲（Outline）         | 右侧显示标题结构                  |
| 关系图谱（Graph）         | 可视化笔记网络                   |
| 标签面板 / 文件浏览器        | 基础导航                      |
| 画布（Canvas）          | 白板（见第六节）                  |
| 笔记重组（Note Composer） | 合并/拆分笔记，整理利器              |
| 书签（Bookmarks）       | 钉住常用 MOC 和笔记              |

### 3.2 社区插件：装哪些、怎么装

1. 设置 → 社区插件 → 关闭"安全模式" → 浏览。
2. 搜索安装。推荐清单（按优先级）：

| 插件                 | 解决什么                | 备注                   |
| ------------------ | ------------------- | -------------------- |
| **Dataview**       | 用查询把笔记当数据库          | 进阶必备，第四节专讲           |
| **Templater**      | 模板 + 脚本，自动化填充       | 第五节专讲                |
| **Obsidian Git**   | 自动备份 Vault 到 GitHub | 数据安全底线               |
| **Excalidraw**     | 手绘/流程图白板            | 第六节                  |
| **QuickAdd**       | 一键捕获、宏              | 配合 Templater 做 Inbox |
| **OmniSearch**     | 全文语义搜索              | 笔记多了之后必装             |
| **Smart Composer** | 在笔记里直接用 AI 写/改      | 见第十节，本仓库主打           |

### 3.3 装插件的纪律

- **一次装一个，验证一个**：别一口气装十个，出问题不知道是谁。
- **读权限**：社区插件能读你所有文件。只装口碑好、开源、更新活跃的。
- **Git 兜底**：装新插件前先 `git commit` 一次，翻车能回滚。

## 四、Dataview：用查询把笔记变成数据库

Dataview 让你用类 SQL 的语法，从带 YAML 元数据的笔记里动态捞出列表。这是"笔记变系统"的关键一步。

### 4.1 先给笔记加元数据（frontmatter）

每篇原子笔记顶部加一段 YAML：

```markdown
---
title: 阻抗建模
type: concept
topic: 电力电子
status: 研读中
created: 2026-08-21
---

正文……
```

### 4.2 在笔记里写查询

```markdown
```dataview
TABLE status, topic FROM "01-Concepts"
WHERE type = "concept" AND topic = "电力电子"
SORT created DESC
```
```

渲染出来就是一个自动更新的表格：你每加一篇符合条件的笔记，它自动出现。

### 4.3 实用查询范式

- **待整理清单**：`LIST FROM #待整理 SORT file.mtime DESC`
- **本周新笔记**：`LIST WHERE file.cday >= date(today) - dur(7 days)`
- **按状态分组**：`TABLE status FROM "01-Concepts" GROUP BY status`

> 进阶：DataviewJS 能用 JavaScript 写更复杂的聚合。新手先吃透 TABLE/LIST/SORT/WHERE 四件套即可。

## 五、Templater：用脚本让模板会思考

核心插件"模板"只能静态填充；**Templater** 能执行 JS，让模板在创建时自动算日期、插变量、调 API。

### 5.1 基础：自动填日期

模板文件 `Templates/每日笔记模板.md`：

```markdown
<% tp.date.now("YYYY-MM-DD dddd") %>
# <% tp.date.now("YYYY-MM-DD") %> 日记

## 今天学了
- 

## 待办
- [ ] 
```

创建日记时，`<% %>` 会被实时求值，自动填入今天日期。

### 5.2 进阶：从笔记里提取变量

```javascript
<%*
const title = await tp.system.prompt("笔记标题");
tR += "---\ntitle: " + title + "\ncreated: " + tp.date.now("YYYY-MM-DD") + "\n---"
%>
```

这段会弹窗问标题，再把元数据写进 frontmatter。

### 5.3 配合 QuickAdd 做 Inbox 捕获

QuickAdd 的"Capture"能把一条临时想法一键塞进 `00-Daily/Inbox.md`，Templater 负责格式化。每天清空 Inbox，把条目分流到对应 MOC——这就是你的"第二大脑"日常运转方式。

## 六、Canvas 与 Excalidraw：视觉化思考

文字适合沉淀，图适合推演。

### 6.1 Canvas（核心插件，原生）

- 白板式画布，可放笔记卡片、图片、网页嵌入、其他 Canvas。
- 用法：做**单篇长文的结构草图**、**项目脑暴**、**论文框架**。
- 卡片可双向链接到正式笔记，草图成熟后"长"成原子笔记。

### 6.2 Excalidraw（社区插件）

- 手绘风流程图/架构图，适合画**系统框图、信号流、心智模型**。
- 与 Canvas 区别：Excalidraw 偏"画"（自由线条、箭头、手写感），Canvas 偏"排"（卡片网格）。
- 科研/工程场景：用 Excalidraw 画拓扑和原理图，导出 PNG 嵌回笔记。

## 七、关系图谱调优：让网络真正有用

默认图谱是一团毛线。本仓库的 `graph-optimizer` 包就是干这个的，但这里讲**原理**。

1. **按文件夹/标签着色**：图谱设置里按 `path` 或 `tag` 上色，一眼区分"概念/书籍/课程"。
2. **控制节点数**：图谱只显示当前文件夹，避免全库糊成一团。
3. **用标签过滤**：输入 `#电气` 只看相关子网。
4. **消除孤立节点**：没有被任何笔记链接的笔记是"死知识"，定期回链或合并。

> 本仓库 `graph-optimizer-v1.0.zip` 提供图谱分色 + 侧边栏着色 + 链接着色 + Callout 美化，解压到 Vault 根目录激活 CSS Snippet 即可（详见 `graph-optimizer/README.md`）。

## 八、定期复盘：让知识滚动起来

没有复盘，Vault 会变成仓库而不是大脑。

### 8.1 日盘点（5 分钟）

每天清空 Inbox，把临时捕获分流进 MOC；给当天日记加 `[[链接]]` 到相关概念。

### 8.2 周回顾（30 分钟）

- 打开 `MOC-学习笔记`、`MOC-研究`，看哪些概念被反复引用（反链最多 = 核心）。
- 用 Dataview 拉"本周新笔记"和"待整理"清单，处理掉。
- 合并重复笔记，升级 MOC 结构。

### 8.3 月收敛（1 小时）

- 把一个月的日记压缩成几篇"主题复盘"笔记。
- 识别知识盲区（某个 MOC 长期空着 = 你一直没碰的领域）。

## 九、发布：把 Vault 变成网站或协作文档

笔记写好了，想分享或长期保存：

| 方式 | 工具 | 适合 |
|------|------|------|
| 静态网站 | **Obsidian Publish**（官方，付费） | 公开知识库 |
| 自托管 | **Quartz** / **ObsidianHtml**（开源） | 免费、可部署到 GitHub Pages |
| 协作文档 | 导出 Markdown 到飞书/Notion | 团队共享 |
| 备份 | **Obsidian Git** 自动推 GitHub | 数据安全底线 |

> 推荐 Quartz：把 Vault 推到 GitHub，Actions 自动生成网站，免费且全量保留双向链接。

## 十、AI 整合：把 AI 嵌进每条工作流

这是本仓库的主题。AI 不是"另一个聊天框"，而是嵌进上面每一步的协作者。

### 10.1 写作时（Smart Composer，本仓库主打）

- 在笔记里直接让 AI 续写、改写、总结，带 diff 视图，不破坏原文。
- 配置 Claude API 后用 `claude-opus` / `claude-sonnet` 做深度写作。

### 10.2 整理时（Smart Connections + Claude Code）

- **Smart Connections**：基于 Embeddings 发现笔记间的语义关联，补双向链接的盲区。
- **Claude Code 指向上级 Vault 文件夹**：让 AI 读整个知识库当上下文，做"跨笔记综述""找矛盾""生成新 MOC"。这是个人知识库的"Agent 化"。

### 10.3 检索时（AI 问答）

- 问"我之前关于弱电网稳定性的结论是什么"，AI 从 Vault 检索回答并附来源笔记链接。
- 配合 OmniSearch 做语义检索，比关键词搜索更准。

### 10.4 自动化时（AI + 脚本）

- QuickAdd + Templater 捕获时，让 AI 自动打标签、抽关键词、写一句话摘要进 frontmatter。
- Dataview 用 AI 生成的 `summary` 字段做概览页。

> 红线：**AI 生成内容必须标注来源、必须你过目**。Vault 是你的第二大脑，不是 AI 的草稿纸。本仓库 `AI-SETUP-GUIDE.md` 可丢给 AI 自动配好整套环境。

## 十一、常见坑与排错

| 现象 | 原因 | 解决 |
|------|------|------|
| 双向链接不生效 | 笔记名含特殊字符/空格 | 用 `[[笔记名]]` 精确匹配，避免重名 |
| Dataview 不出结果 | 没开 Dataview 插件 / 元数据格式错 | 检查 frontmatter 缩进、字段名 |
| Templater 不执行 | 模板语法错误 / 没设模板文件夹 | 看控制台报错，`<% %>` 要成对 |
| 图谱一团乱 | 节点太多没过滤 | 按文件夹/标签着色、限制范围 |
| 插件装完崩溃 | 插件冲突 / 版本不兼容 | `git` 回滚，逐个重装 |
| AI 改写吞了原文 | 没开 diff 视图 | 用 Smart Composer 的 diff 模式 |
| 同步冲突 | 多设备同时改同文件 | 用 Obsidian Git，改前先拉 |

## 结语

1. Obsidian 的价值不在"记"，在"连"——一条被十篇引用的概念笔记，胜过十篇孤岛日记。
2. 插件体系的核心三件套是 Dataview（查）+ Templater（写）+ Git（保），其余按需。
3. AI 是嵌进每条工作流的协作者，不是另一个聊天框；红线是"AI 内容必标注来源、必你过目"。
4. 定期复盘决定 Vault 是"大脑"还是"仓库"——日清 Inbox、周理 MOC、月收敛日记。
